# UI 与交互规范

## 1. 设计基线

- 保留当前暖色浅色体系：页面米白、卡片象牙白、深灰正文、低饱和青绿色强调色。
- 保持现有简洁工具感，不引入深色模式、渐变、玻璃拟态或额外装饰。
- PC 最大内容宽度沿用现有页面基线；移动端支持最小 320px。
- PC 与移动端使用相同的信息架构和功能顺序，仅响应式重排。

## 2. 页面结构

从上到下：

1. 统一 Achilles Cat 头部：品牌、Works、Archive、MiuMiu、Lab、语言和 Settings。
2. 标题与说明，以及紧随其后的静态使用指南条带。
3. 对齐预览舞台；空状态、加载状态和错误状态下的上传区域位于舞台内部。
4. 当前预览模式标识；不提供独立的预览导航按钮。
5. 当前预览控件与导出操作。
6. 版本、隐私政策、反馈页脚。

页面不再展示 Split Preview，但保留布局切换能力。

Works、Archive、MiuMiu 和 Settings 当前为非交互占位；Lab 和语言切换是实际可用的头部交互。

v1 不新增 Split Preview 功能；若已有 Split Preview 组件未被其他流程使用，应在组件清理阶段移除，而不是重新挂载。

## 3. 上传区域

- 上传区域作为对齐预览舞台内部的 `stage-input` 内容出现，仅在空状态、加载状态和错误状态显示。
- 整块区域可点击，也支持拖拽文件。
- 文字整体水平和垂直居中，不显示右侧“选择图片”按钮。
- 默认文案说明支持 JPG、PNG、MPO 和本地处理。
- 拖入时显示明确边框/背景反馈。
- 上传/解析时显示遮罩、加载图标和当前动作，阻止重复上传。
- 已有图片时上传新文件，直接替换并清除旧设置，不弹确认框。

## 4. 预览状态与公共尺寸

- 不提供“对齐预览”和“Wiggle 预览”的独立导航按钮；控制区只显示当前模式。创建 Wiggle 后进入 Wiggle 预览，点击“调整对齐”返回对齐预览。
- 两种预览的图片显示区域高度、宽度和背景一致。
- PC 延续现有 `height: clamp(360px, 48vw, 520px)` 的视觉基线。
- 移动端在相同容器内按可用宽度显示图片，切换不改变容器高度。
- 图片保持真实比例并完整显示；剩余空间使用统一 Matte Background。

## 5. 对齐预览

- 显示左右眼叠加画面。
- 图片右上角显示布局切换图标；图标表达“点击后将切换到的布局”。
- JPG/PNG 点击图标切换 SBS/Top-Bottom，并重新解析当前源文件。
- MPO 同样显示图标但置灰，提示“仅适用于 JPG/PNG 拼接图”。
- 图片下方留出与 Wiggle 控件相同的 15px 视觉间距。
- PC：水平、垂直、叠加强度和“重置对齐”同一行，Reset 位于最右侧。
- 移动端：三个滑杆和 Reset 纵向排列，保证触控宽度。
- “创建 Wiggle”位于对齐控件下方，独占整行；样式与“下载”一致。

## 6. Wiggle 预览

- 创建完成后自动切换到此视图并播放。
- 五个控件按纵向排列：播放/暂停、Speed、交换左右眼、中间帧开启/关闭、调整对齐。
- Speed 保留标准输入框外观，显示 `ms`。
- 桌面端和移动端均保持纵向控件顺序，并保证触控目标尺寸。
- “下载”位于控制行下方，独占整行，与“创建 Wiggle”同样式。

控制区同时提供“删除”动作。删除会释放当前预览资源、清空当前源文件、使相关异步任务失效，并恢复初始空状态。

## 7. 使用指南条带

- 位于 Lab 标题、说明和本地处理提示之后，工作区之前。
- 使用一条轻量编辑型横向索引，不创建教程页或弹框。
- 包含四个步骤：上传立体图像、对齐图像、预览深度运动、导出结果。
- 中英文同时显示或随全局语言切换显示，不出现混合状态。
- 使用细线分隔、DM Mono 步骤编号和简短文案；不使用 SaaS 帮助中心卡片。

## 8. 下载弹框

- 无右上角 X。
- 普通 JPG/PNG 仅显示 GIF；MPO 显示 GIF 与 SBS PNG。
- GIF 显示 Small、Medium、Large，以及各自预计文件大小。
- SBS PNG 显示预计文件大小，并按当前 `Swap Eyes` 顺序输出左右眼。
- 选择 GIF 时显示“导出取景”选项：默认“裁切重叠区”，可选“完整画面（保留边缘背景）”。切换到 SBS PNG 时隐藏该选项。
- 选项下方显示可见说明：“裁切重叠区：无白边，边缘会裁切”；“完整画面：保留全部内容，可能出现边缘背景”。
- 裁切重叠区的预计大小使用裁切后的实际输出尺寸；完整画面使用完整画布尺寸。切换取景后立即更新预计大小及 Small、Medium、Large 的可用/禁用状态。零对齐偏移时两项输出一致。
- 导出取景不写入本地记忆；每次打开下载弹框均默认“裁切重叠区”。
- 所有大小明确使用“预计”语义。
- 初始选择 GIF + Medium；后续使用上次有效选择。
- 底部为取消与确认操作。
- 导出时弹框主操作区显示进度遮罩，确认按钮禁用；取消导出不被遮罩和禁用。首次点击“取消导出”只中止导出并保留弹框，恢复后再次点击“取消”关闭弹框。
- 打开弹框时 Wiggle 继续播放。

隐私弹框中的匿名产品事件开关默认关闭；只有用户明确开启后才允许发送分析事件，关闭弹框本身不构成同意。

## 9. 顶部消息

- 页面顶部居中，视觉接近 Element Plus ElMessage。
- 支持成功、信息、警告、错误状态，使用图标和颜色共同表达，不只依赖颜色。
- 普通消息自动消失；错误停留更久；同类型、同内容消息合并。
- 下载完成文案只显示“已下载”。
- 消息区域使用 `aria-live`，不抢夺当前焦点。

## 10. 加载状态

- 上传/解析：锁定上传区或主工作区，显示“正在读取/正在解析”。
- 创建 Wiggle：锁定主工作区，显示“正在创建 Wiggle”。
- 导出：只锁定下载弹框主操作区和确认按钮，显示阶段、百分比和进度条。
- 取消按钮始终可点击。
- 加载结束、失败或取消后恢复原状态，不留下透明遮罩拦截点击。
- `prefers-reduced-motion` 下用静态状态图标或非旋转进度表现。

## 11. 中英文与文案

- 首次默认中文。
- 切换后本地记忆，刷新保持。
- 英文布局不得依赖中文短文案宽度；按钮允许换行但不截断。
- 产品名、文件格式、尺寸名和错误诊断码保持原样。

## 12. 无障碍与移动端

- 所有图标按钮必须有中英文 `aria-label` 和可见/悬停提示。
- 键盘可操作上传、创建 Wiggle、调整对齐、布局切换、删除、滑杆、弹框和下载。
- 弹框打开后焦点进入弹框，关闭后返回触发按钮；Escape 行为保持一致，即使没有右上角 X。
- 触控目标至少 44 × 44px；移动端不依赖 hover 才能获得必要说明。
- 200% 缩放和 320px 宽度下无水平滚动。

## 13. v1 设计与字体交付约束

- 正式代码修改前，必须先确认 Homepage 与 3D Photo Lab 两张 Desktop 高保真设计稿。
- 设计依据位于 `docs/design/DESIGN_CONCEPTS.md`，作为 v1 已批准的设计概念基线并纳入 Git 版本控制。
- 设计稿确认前只允许更新文档、字体资产和视觉参考，不修改 Vue、TypeScript 或业务样式实现。
- `Editorial Serif` 角色使用实际 `Instrument Serif` 字体文件。
- `Space Grotesk` 与 `DM Mono` 使用项目内实际字体文件，不依赖远程字体请求。
- 全项目页面、导航、弹框、状态、错误和页脚必须覆盖中英文。
- 本轮仅重排现有流程，不新增旋转、视频导出、Split Preview 或其他业务能力。
