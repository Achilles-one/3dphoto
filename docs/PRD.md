# 3D Photo Enhancer 产品需求

## 1. 文档状态

- 版本：v0.9
- 更新日期：2026-09-08
- 产品阶段：公开 Beta
- 本文是产品范围、用户流程和功能验收的唯一依据。
- UI 细节以 `UI.md` 和 `pages/` 为准，开发循环以 `DEVELOPMENT.md` 为准，代码边界以 `ARCHITECTURE.md` 为准，真实文件兼容以 `COMPATIBILITY.md` 为准，发布方式以 `DEPLOYMENT.md` 为准。

## 2. 产品定位

3D Photo Enhancer 是浏览器内运行的双视图照片工具。用户上传 SBS、Top-Bottom 或 MPO 照片，完成布局确认、左右眼对齐、Wiggle 预览并下载 GIF 或 MP4；MPO 还可导出 SBS PNG。

图片内容默认只在浏览器本地处理，不上传服务器。本产品不从普通单张 2D 照片生成真实 3D，不承诺修复严重旋转、缩放、透视、镜头畸变或不同时间拍摄造成的主体运动。

## 3. 必须支持的输入

- JPG/JPEG：左右拼接 SBS、上下拼接 Top-Bottom。
- PNG：左右拼接 SBS、上下拼接 Top-Bottom。
- MPO：至少兼容仓库中的 FUJIFILM 真实样本。
- Weeview 32.51MP SBS：8064 × 4032，总像素 32,514,048，每眼 4032 × 4032，属于必须通过的正式兼容基线，不能因预览降采样、内存保护或 UI 重构而失去支持。

不支持作为输入：普通单张 2D 照片、HEIC、WebP、视频、压缩包、两张独立照片上传。

## 4. 核心流程

1. 空状态时，用户在对齐预览舞台内部点击上传区域或将文件拖入该区域。
2. 页面显示上传/解析遮罩；新文件会直接替换旧文件，并清除旧文件的布局、对齐、播放和导出临时状态。
3. 解析完成后直接进入“对齐预览”，不再显示 Split Preview；预览控制区不提供独立的模式导航按钮，只显示当前模式。
4. JPG/PNG 可用右上角图标切换 SBS 与 Top-Bottom；MPO 始终显示该图标但置灰，并提示“仅适用于 JPG/PNG 拼接图”。
5. 页面在后台尝试自动识别主要主体视差平面并填入水平、垂直偏移；成功或失败均保留现有对齐预览与手动调节能力。用户可继续调整水平、垂直和叠加强度，或使用“重置对齐”。
6. 用户点击“创建 Wiggle”；页面显示创建遮罩，完成后自动进入 Wiggle 预览并自动播放。
7. 用户设置每帧间隔、暂停/播放、交换左右眼、开启/关闭中间帧或通过“调整对齐”返回对齐预览。
8. 用户可点击“删除”，由页面执行完整删除流程：使上传、创建和布局切换任务失效，释放当前画布资源，清空当前源文件，并将状态恢复到初始状态。
9. 用户打开下载弹框，选择输出格式和尺寸并开始导出。
10. 导出时只锁定弹框主操作区和确认按钮，取消导出始终可用。
11. 下载成功后顶部只提示“已下载”，不显示最终文件大小。

## 5. Wiggle 规则

- 中间帧默认关闭；开启时固定 `A → M → B → M` 四帧，M 为 A 100% 后叠加 B 50%。
- 中间帧关闭时固定 `A → B` 两帧。
- 切换中间帧后立即从新序列开始播放，并直接影响 GIF 与 MP4 导出。
- Speed 表示每帧间隔，只接受 100–2000 的整数毫秒，默认 200ms。
- 200ms 时，四帧完整循环为 800ms，两帧完整循环为 400ms。
- 预览与导出必须使用相同的左右眼顺序、对齐参数、帧序列和帧间隔。
- 不提供 Wiggle Amount、帧数自定义或 Speed Reset。

## 6. 对齐与画面规则

- 对齐预览将两眼画面叠加显示，不并排显示。
- 调节项为水平偏移、垂直偏移、叠加强度。
- 水平与垂直偏移的可调上限统一为单眼最短边的 20%。
- “重置对齐”只重置上述三项。
- 自动主体对齐在左右眼拆分并显示对齐预览后于浏览器本地执行，只计算现有水平、垂直偏移，不修改左右眼像素、不自动裁切，也不处理旋转、缩放、透视、镜头畸变或严重主体运动。
- 第一版的“主体”定义为画面中央区域附近、空间相对集中、具有足够纹理且左右眼水平视差一致的主要匹配点集合；算法选择该集合代表的主要视差平面，不承诺语义识别用户心中的任意主体。
- 自动对齐先使用全画面可靠匹配估计统一垂直偏移，再使用主要主体匹配集合的稳健中位水平视差确定水平偏移；水平偏移只改变零视差平面，必须保留前景、主体与背景之间的相对水平视差。
- 自动结果只有在匹配数量、空间覆盖、垂直一致性、主体候选区分度和结果校验均达到置信度要求时才应用；置信度不足、超出合法范围或运行失败时不得修改当前对齐参数，并提示用户手动调节。
- 单次自动对齐从任务启动起最长运行 30 秒；超过 30 秒必须终止 Worker，以 `timeout` 失败原因结束并退出“正在识别主要主体”状态。超时与其他安全失败相同，不修改当前对齐参数，用户可立即继续手动调节。
- 自动对齐运行期间手动滑块、重置、创建 Wiggle、新上传、删除和布局切换均优先于自动任务；这些动作必须取消或使旧任务失效，迟到结果不得覆盖用户操作或新图片。
- JPG/PNG 切换 SBS 与 Top-Bottom 后应基于新的左右眼拆分重新尝试自动对齐；MPO 使用已应用各自 Orientation 的前两个有效视图。
- 自动对齐结果只写入现有水平、垂直偏移，因此预览、Wiggle、GIF 和 MP4 继续共享相同参数；MPO 原尺寸 SBS PNG 不应用对齐偏移。
- 预览及选择“完整画面（保留边缘背景）”的 GIF、MP4 保持完整画面和真实比例，不通过自动裁切或缩放隐藏偏移边缘；只有用户在下载弹框显式选择“裁切重叠区”时才裁切共同可见区域。
- 露出区域使用统一 Matte Background。

## 7. 下载规则

- 普通 JPG/PNG：可导出 GIF 或 MP4。
- MPO：可导出 GIF、MP4 或原始解码尺寸的 SBS PNG。
- SBS PNG 输出遵循当前 `Swap Eyes` 顺序：关闭时为物理左眼 → 物理右眼，开启时为物理右眼 → 物理左眼；该顺序与当前预览的左右眼顺序一致。
- GIF 默认格式为 GIF，默认尺寸为 Medium；Small、Medium、Large 的最大边分别为 720、1024、1440，禁止无提示放大源图。
- MP4 使用 H.264 编码、25fps、无音频和 VBR 高质量配置；提供 1080、1440 两档，分别表示最长边 1080、1440，并保持源图宽高比且禁止放大源图。最终编码宽、高均向下调整为偶数，以适配 YUV 4:2:0。
- MP4 重复当前完整 Wiggle 循环：单循环不超过 4 秒时，重复到总时长至少 2 秒且不超过 4 秒；单循环超过 4 秒时只保留一个完整循环。MP4 文件本身不承诺无限循环，播放结束后的循环行为由播放器决定。
- MP4 使用按实际输出像素计算的目标码率：`宽 × 高 × 25 × 0.6 bit/s`；1080 档限制在 8–20 Mbps，1440 档限制在 16–50 Mbps。上下限是 VBR 目标码率的钳制范围，不表示固定使用最高码率。
- GIF、MP4 下载弹框提供“导出取景”：默认“裁切重叠区”，可选“完整画面（保留边缘背景）”。
  - 裁切重叠区：同时使用当前水平与垂直对齐参数，并以 Swap Eyes 后的最终绘制顺序计算两眼共同可见区域；A、B、M 帧共用同一裁切区域。交集边界向内取整，避免残留单像素边缘背景。两眼原始尺寸不一致的 MPO GIF/MP4 同样按最终绘制后的共同可见区域计算。裁切后的宽高比允许随对齐偏移变化，不拉伸回原比例；GIF 再按 Small、Medium、Large，MP4 再按 1080、1440 的最长边规则缩放输出，因此无白边但会裁切边缘。
  - 完整画面：保留完整画布与现有 Matte Background，不裁切、不拉伸，可能出现边缘背景。
  - 预计文件大小、内存预算和各尺寸的可用状态均按所选取景后的实际输出尺寸计算；切换取景后立即重新计算。完整画面沿用完整画布尺寸。
  - 该选择只影响本次 GIF 或 MP4 导出，不影响 Wiggle 预览、MPO SBS PNG 或后续下载弹框；不写入本地记忆，每次打开弹框均默认“裁切重叠区”。零对齐偏移时两个选项的输出一致。
- 下载弹框记住用户上一次有效的格式与尺寸选择；选择对当前文件无效时回退到 GIF + Medium。
- 默认导出选择继续保持 GIF + Medium；MP4 是用户主动选择的高清格式，不因浏览器缺少 MP4 编码能力而自动切换到其他视频格式。
- GIF、MP4 每个尺寸均显示预计文件大小；MPO 的 SBS PNG 也显示预计文件大小。预计值不是最终值，不得写成精确大小。
- MPO 两眼尺寸不一致时阻止 SBS PNG 导出，并给出顶部错误消息。
- 导出支持取消；导出期间首次点击“取消导出”只中止导出并保留下载弹框，取消后再次点击“取消”才关闭弹框；取消或失败后保留当前编辑状态。

## 8. 全局界面规则

- 统一头部包含 Achilles Cat、Works、Archive、MiuMiu、Lab、语言和 Settings；Works、Archive、MiuMiu 与 Settings 当前均为非交互占位，只有 Lab 和语言切换有实际行为。
- 默认语言为中文，可切换英文；语言选择本地记忆，覆盖页面、弹框、顶部消息、隐私政策和反馈文字。
- 使用指南位于 3D Photo Lab 标题、说明和本地处理提示之后，以静态四步编辑型条带呈现，不使用教程页或弹框。
- 版本、隐私政策和反馈位于页面底部。
- 成功、警告、错误等消息采用顶部居中的 ElMessage 式提示；同类消息合并，普通消息自动消失，错误停留更久。
- 上传解析、创建 Wiggle、导出均有清晰的加载状态，且遵守 `prefers-reduced-motion`。
- 打开下载弹框时，Wiggle 继续播放；使用指南是静态内容，不改变播放状态。

## 9. 隐私与反馈

- 图片像素、原始 MPO 内容和输出文件不上传。
- 分析默认关闭；只有用户在隐私弹框中明确开启匿名产品事件后才允许发送。用户未作选择、关闭弹框或明确关闭时均不得发送。
- 分析事件不得包含文件名、图片内容、原始字节或可逆图片标识。
- 反馈只附带版本、构建号、浏览器、输入格式、导出选项（格式、尺寸与 GIF/MP4 导出取景）和错误码，不附带文件名或图片内容。仅在用户点击“确认下载”后记录该次导出选项；即使随后导出失败或取消，仍保留该次尝试用于反馈诊断。尚未尝试导出及 SBS PNG 的导出取景均标记为不适用。

## 10. 发布最低条件

- v1 视觉实现前必须先确认 Homepage 与 3D Photo Lab Desktop 设计稿及验收清单。
- `docs/design/DESIGN_CONCEPTS.md` 保留为 v1 已批准的设计概念基线，纳入 Git 版本控制。
- 桌面端和移动端布局符合 `UI.md`，无横向溢出。
- Weeview 32.51MP SBS 与 FUJIFILM MPO 核心流程通过。
- 中英文、顶部消息、三个加载状态和下载取消可用。
- Preview 与导出帧语义一致。
- `npm run release:check` 通过。
- Vercel Preview 验收通过后，才能合并到生产分支。

## 11. 暂不进入本轮

- 两张独立图片上传。
- Split Preview 可见页面入口；保留既有状态定义时不得在 UI 中展示该模式。
- 旋转、缩放、透视和镜头畸变修复。
- 红蓝 3D、WebM/APNG/WebP。
- AI 深度、新视角生成、在线分享、账号、云存储、批量处理。
