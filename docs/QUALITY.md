# 质量门禁

## 1. 通用完成条件

- 功能流程有明确的成功、加载、取消、失败和空状态。
- 旧异步任务不能覆盖新输入或已删除的图片。
- 画布、渲染器、观察器、计时器和导出临时资源在替换、取消和卸载时可释放。
- 键盘、焦点、ARIA 状态、错误消息和 `prefers-reduced-motion` 行为可用。
- 中英文文案不截断、不混用，移动端无横向溢出。
- 预览和导出使用一致的左右眼顺序、对齐参数、帧序列和帧间隔。
- 自动主体对齐只在置信度达标时提交；低置信度和运行失败不改变现有偏移，手动操作、新输入和删除后的迟到结果不能提交。
- 自动主体对齐必须在 30 秒内成功或以 `timeout` 安全失败；成功、Worker 错误、主动取消和超时路径均清除计时器与 Worker 引用，界面不得遗留运行状态。

## 2. CSS 收敛完成标准

CSS 只有同时满足以下条件，才可标记为“已收敛”：

- 当前活动 DOM、组件职责和 CSS 入口已有清单；每个活动组件只有一个基础样式归属。
- 每个活动选择器只保留一个基础定义；状态、断点和无障碍规则是明确的局部变体，不得继续追加历史阶段覆盖层。
- 基础选择器不依赖 ID 提升优先级；应用挂载点等结构性宿主如必须使用 `#app`，必须用 `:where()` 包裹。普通上下文选择器优先使用单一 class 或元素选择器，复杂上下文使用 `:where()` 限制优先级。
- 正常样式不得依赖 `!important`；仅允许 `prefers-reduced-motion` 等无障碍强制覆盖使用。
- 响应式规则集中在样式文件末尾；每个断点只有一个职责明确的规则块，并复用同一 DOM，不复制桌面和移动两套组件样式。
- 颜色、字体、间距、圆角、阴影、动效和断点优先引用设计 token；不得为修复局部覆盖重新引入同义硬编码值。
- 已确认的空状态、对齐、Wiggle、导出、错误、隐私弹框和删除重置状态，在冻结视口下无未解释的视觉回归。
- `npm run build`、相关测试、`git diff --check` 和必要的桌面/移动截图验证均通过；截图或审计结果能说明基线没有被静默改变。

完成后，后续 CSS 修改必须先说明影响的职责区块、选择器优先级和视觉基线；若需要突破以上规则，应先记录设计或架构决策。

## 3. 必须回归的核心路径

1. 空状态上传 JPG/PNG/MPO。
2. JPG/PNG 布局切换与 MPO 禁用布局切换。
3. 自动主体对齐成功、安全失败、手动接管、对齐、创建 Wiggle、播放/暂停和调整对齐。
4. 删除后回到初始状态，并确认旧任务不会恢复。
5. GIF 两帧/四帧导出、取景选择、取消和失败恢复。
6. MP4 两帧/四帧导出、1080/1440、不放大、偶数尺寸、25fps 时间轴、完整循环、VBR 码率、能力禁用、取消和失败恢复。
7. MPO GIF、MP4 与 SBS PNG 导出限制，包括 `Swap Eyes` 输出顺序。
8. 隐私同意：默认关闭、明确开启后发送、关闭后不发送。

## 5. 证据记录

每次完成一个可交付变更，记录实际执行的验证和结果；失败时记录首个真实错误与最小修复。真实照片和设备样本不得因方便而提交到仓库、CI 或部署产物。

自动主体对齐的合成测试至少覆盖已知正负 X/Y 偏移、主体与背景具有不同水平视差、轻微曝光差、低纹理、重复纹理、遮挡、主体歧义和越界结果。算法成功时验证主体残余垂直误差和水平稳定性；无法确定主体时验证安全失败，不以“始终返回一个偏移”作为质量目标。

异步测试必须覆盖上传时的“Vue 响应式代理与原始 `stereoSplit`”以及布局切换后的“当前状态代理与任务输入代理”两种身份校验，证明两侧经 `toRaw()` 解包后有效结果不会被误判为过期；使用可控 Worker 和假计时器验证 30 秒前不超时、达到 30 秒返回 `timeout`，并分别断言成功、Worker 错误、主动取消和超时都只结算一次、清除计时器、终止或释放 Worker，且 `running` 状态结束。

生产构建检查必须验证自动对齐 Worker 使用冻结的 OpenCV `5.0.0` + Emscripten/emsdk `4.0.20` CSP-safe OpenCV.js/WASM，核对 `src/vendor/opencv/5.0.0/` 中的构建清单和 SHA-256，并确认常规 CI/Vercel 没有重新下载或编译 OpenCV。首页和普通脚本维持 `script-src 'self'`，自动对齐 Worker 响应 CSP 额外加入 `'wasm-unsafe-eval'` 且不包含 `'unsafe-eval'`；`.wasm` 使用内容哈希且响应类型为 `application/wasm`，Worker 构建内容带有当前运行时协议版本。Preview/Production 验收必须在实际响应头下初始化并执行一次自动对齐；仅确认 Worker 文件存在、任务结束或界面退出 `running` 均不视为通过。

自动对齐验收必须按输入预期分类：

- 已知可成功的确定性合成样本必须返回 `ok: true`，并断言 `alignmentX/Y` 在预期容差内；`runtime-failure`、`timeout` 或任意业务失败都使该检查失败。该用例负责证明 OpenCV 初始化、Wasm、CSP、Worker 消息和结果提交整条链路可用。
- 低纹理、匹配不足、重复纹理或无明确主体样本允许快速返回 `insufficient-features`、`insufficient-matches`、`vertical-inconsistency`、`subject-ambiguity`、`offset-out-of-range` 或 `validation-failed`，并必须保留手动调节。上述业务安全失败不应导致发布检查失败，但不得返回 `runtime-failure` 或非专门超时测试中的 `timeout`。
- 运行异常与超时使用独立负向测试，分别明确期望 `runtime-failure` 与 `timeout`。Worker 内部必须把 CSP/Wasm 初始化失败与普通“未识别主体”区分记录，UI 可以继续显示非阻断通用提示，但测试和安全诊断必须能够读取稳定失败原因。

## 6. MP4 自动化门禁

- 保留尺寸、码率、循环和累计误差分配的单元测试；另用 Playwright 在 Windows CI 的 Edge 中对生产构建执行真实 WebCodecs H.264 导出。
- CI 使用无隐私、低复杂度的合成 SBS fixture，不使用 Weeview 或 FUJIFILM 真实样本。成功时不保留输入或 MP4；失败时可临时上传合成输入、输出和测试日志。
- 最小真实编码矩阵为：1080、两帧、200ms，预期 5 个完整循环、50 帧、2 秒；1440、四帧、333ms，用于验证真实 1440 输出、累计误差和完整循环。
- 真实 MP4 必须验证：容器可解析、视频编码为 H.264/AVC、只有一条视频轨且无音轨、宽高为偶数且不超过所选最长边、每帧 40ms、平均 25fps、总时长与逻辑完整循环的差异不超过 40ms、下载扩展名为 `.mp4`。
- 同一门禁还必须覆盖：WebCodecs 不支持时禁用 MP4 且 GIF 可用；1080 支持而 1440 不支持时只禁用 1440；导出取消后弹框保留且不下载；导出期间删除或替换输入后旧任务不得下载。
- Windows CI 若无法提供 H.264 WebCodecs 编码能力，任务必须失败并报告运行环境问题，不得将真实编码测试标记为跳过。
- Mediabunny 用于读取容器、轨道、尺寸、帧数和时长；`ffprobe` 仅作为 CI 验证工具确认 `h264`、`yuv420p`、25fps 和无音频，不进入网站运行时依赖或生产构建。
