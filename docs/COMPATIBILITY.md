# 真实文件兼容与验收

## 1. 兼容目标

真实 Weeview 32.51MP SBS 和 FUJIFILM MPO 都是发布必须支持的输入，不是可选测试样本。UI 重构、内存预算、预览降采样和导出优化不得降低这两类文件的成功率。

## 2. Weeview 32.51MP SBS

仓库当前真实样本：

- `sid_2000_0101_053037_001.JPG`
- `sid_2000_0101_053041_001.JPG`
- `sid_2000_0101_053044_001.JPG`
- `sid_2000_0101_053048_001.JPG`

共同基线：

- 文件尺寸：8064 × 4032。
- 总像素：32,514,048，即 32.51MP。
- 布局：SBS。
- 单眼逻辑尺寸：4032 × 4032。
- 文件大小约 7.5–8.3MiB。

必须验收：

1. 文件可点击和拖拽上传，不被文件大小或像素预算误拦截。
2. 上传时 UI 保持响应并显示解析状态。
3. 预览允许降采样，但导出不得从低分辨率预览源二次放大。
4. SBS 切分无一像素错位，切换 Top-Bottom 后可切回且不丢文件。
5. 水平、垂直、叠加强度、Reset 正常。
6. 两帧和四帧预览正常，默认 200ms 语义正确。
7. Small、Medium、Large GIF 能按安全预算导出；若设备预算确实不足，应禁用不可执行档位并提供较小档，不得让页面崩溃。
8. 取消导出、失败重试、重新上传无需刷新页面。

## 3. FUJIFILM MPO

仓库当前真实样本：

- `DSCF3439.MPO`
- `DSCF3440.MPO`
- `DSCF3441.MPO`
- `DSCF3442.MPO`

当前可见首帧基线：3584 × 2016，单文件约 6.5–6.7MiB。解析必须继续以 MPF 中的图像条目和 EXIF Orientation 为依据，不能只把 MPO 当作普通 JPEG。

必须验收：

1. 成功读取前两张有效图像并应用各自 Orientation。
2. 左右眼显示和 Swap Eyes 与导出一致。
3. 对齐预览、两/四帧 Wiggle 和三档 GIF 可用。
4. 布局切换图标可见但置灰，提示“仅适用于 JPG/PNG 拼接图”。
5. 下载弹框显示 GIF 与 SBS PNG。
6. SBS PNG 使用原始解码尺寸，不进行有损 JPEG 重编码；输出顺序遵循当前 `Swap Eyes` 设置；两眼尺寸不一致时阻止导出。
7. 预计文件大小明确标为预计。
8. 多图 MPO 只使用前两张有效图像，并对额外图像给出非阻断提示。

## 4. 浏览器与设备矩阵

发布前最低覆盖：

- Windows Chrome 或 Edge：完整自动化与人工视觉验收。
- 桌面 WebKit/Safari：上传、Canvas、GIF Worker、下载。
- iOS Safari：触控、弹框内部滚动、GIF/SBS 保存。
- Android Chrome：触控、低内存降级、下载。
- 320px、390px、768px、桌面宽度和 200% 页面缩放。

## 5. UI 回归

- 对齐预览与 Wiggle 预览图片区域高度完全一致。
- 320px 下无水平滚动。
- Wiggle 控件按纵向排列；桌面端和移动端均保持相同的控件顺序。
- 预览控制区不提供独立模式导航，只显示当前模式；创建 Wiggle 和“调整对齐”负责进入两个预览状态。
- 删除图片后，当前源文件、预览画布和相关异步任务均被清理，页面恢复初始空状态。
- 上传区域位于对齐预览舞台内部的空/加载/错误状态中。
- 上传、创建、导出三个加载状态不会遗留点击拦截层。
- 使用指南和下载弹框没有右上角 X，底部操作可见。
- 中英文均无按钮文字截断。

## 6. 输出回归

- 四帧序列为 `A、M、B、M`；两帧序列为 `A、B`。
- A/B 相同时 M 不明显变灰。
- Preview/GIF 的构图、Matte、Alignment、Swap Eyes、帧间隔一致。
- GIF 选择“裁切重叠区”时，按原始解码尺寸的水平与垂直对齐及 Swap Eyes 后的最终绘制顺序计算共同可见区域；交集边界向内取整，A、B、M 帧共用该区域并在裁切后缩放。两眼原始尺寸不一致的 MPO GIF 也按最终绘制区域处理；允许宽高比变化且无边缘背景。选择“完整画面（保留边缘背景）”时，保留完整画布与 Matte Background。该选择不影响 MPO SBS PNG；零偏移时两种取景输出一致。
- 切换 GIF 导出取景后，预计大小和各尺寸的内存可用状态按该取景的实际输出尺寸立即更新；点击“确认下载”后，安全反馈诊断保留该次格式、尺寸和取景，即使导出失败或取消；未尝试导出及 SBS PNG 的取景为不适用。
- GIF 无限循环，取消导出后不触发迟到下载。
- SBS PNG 关闭 `Swap Eyes` 时输出物理左眼 → 物理右眼，开启时输出物理右眼 → 物理左眼；必须与当前预览的左右眼顺序一致。

## 7. 样本治理

- 已确认 Weeview 与 FUJIFILM 真实样本不进入 Git，不进入 Vercel 构建产物，也不上传 CI Artifact。
- 真实样本只保存在开发者本地；`.gitignore` 必须明确忽略实际存放目录和常见大小写扩展名，避免误提交。
- Git 中只保存不含图片内容的样本规格：设备、格式、尺寸、像素数、文件字节范围、非敏感哈希和预期结果。若哈希也可能关联外部私人文件，则只保存在本地 manifest。
- CI 使用合成 fixture 验证解析边界和算法；真实设备兼容由发布前本地人工验收承担。PR 涉及输入、内存、预览、Canvas、Worker 或导出时，必须记录 Weeview 与 FUJIFILM 的本地验收结果。
- 测试输出、分析、反馈和 PR 不记录真实文件名或图片内容，只使用设备类型和样本编号。
- 真实样本不得作为页面资源进入公开 Vercel Preview；开发者在浏览器中手动上传仍遵守本地处理边界。

## 8. OG 图片治理

- OG 猫照片允许用于公开分享图并提交 GitHub。
- 两张约 22–23MiB 的 SBS 源 PNG 不作为网站资源提交，只保留在本地设计素材目录。
- Git 只提交最终优化后的 OG 成品，推荐 1200 × 630，并使用适合网页的压缩格式和合理体积。
- OG 成品不得包含私人元数据；生成后检查并移除 EXIF、位置和设备信息。
- 页面使用绝对生产 URL 引用 OG 图片，最终以 `https://www.achillescat.com` 验证社交分享预览。
