# UI 重构与功能实施计划

## 1. 实施原则

- 严格按“页面结构与样式 → 功能模块 → 兼容与发布”的顺序推进。
- 第一阶段只重排页面、组件和样式，不改变现有图像解析、对齐、渲染和导出算法。
- UI 已要求但当前没有实现的行为，第一阶段使用命名明确的空函数占位；占位函数不得伪造成功状态、写入持久数据或改变现有功能结果。
- 每次只推进一个功能模块：执行一次、查看首个真实错误、最小修复、从失败点继续；达到该模块最低验收即停止。
- 不在 UI 重构中顺带重构图像算法、状态架构或导出管线。

## 2. CSS 与组件边界

### 2.1 公共样式

统一放入 `src/styles`：

- 颜色、字体、字号层级、页面背景。
- 通用按钮、输入框、滑杆、禁用态、焦点态。
- 通用卡片、弹框遮罩、顶部消息、加载动画。
- 页面最大宽度、公共间距、桌面/移动断点。
- 无障碍工具类和 `prefers-reduced-motion`。

公共样式只定义可复用视觉规则，不包含某个业务组件的内部定位。

### 2.2 组件特有样式

写在对应 Vue 组件的 scoped style 中：

- 上传区内部排版和拖拽状态。
- 对齐画布上的布局切换图标和状态说明。
- Wiggle 控件的五等分排列。
- 使用指南的步骤与文件类型区。
- 下载选项、预计大小和导出进度区。

### 2.3 禁止事项

- 不在模板中堆叠内联样式。
- 不在全局 CSS 中用业务组件深层选择器覆盖局部实现。
- 不复制一套桌面样式和一套移动样式；使用同一 DOM 结构响应式重排。
- 不为单个按钮创建只有颜色或边距差异的重复类。

## 3. 阶段一：页面与响应式布局

目标：页面与已确认的 PC、移动 UI 图一致，保留现有功能入口，不新增业务实现。

实施顺序：

1. 重建页面外壳：标题、使用指南、语言切换、上传区、预览工作区、页脚。
2. 移除 Split Preview 的可见页面入口；上传成功默认展示对齐预览。
3. 对齐预览和 Wiggle 预览共用同一预览容器尺寸，切换时页面不跳高。
4. 对齐区按“图片 → 间距 → 三个调节器与 Reset → 创建 Wiggle”排列。
5. Wiggle 区按“图片 → 五等分控制行 → 独占一行下载按钮”排列。
6. 加入使用指南、下载弹框、顶部消息和三类加载状态的静态 UI。
7. 完成移动端单列重排、底部式弹框呈现和触控尺寸。

阶段一验收：

- PC 与移动端结构、顺序、间距和按钮分布符合 `ui.md`。
- 对齐/Wiggle 图片区域高度一致。
- 320px 宽度无横向滚动，长中文和英文文案不溢出。
- 现有上传、对齐、预览、下载能力没有因布局改动失效。
- 新功能入口仅调用占位函数，并有统一的 TODO 标识，便于后续逐项替换。

## 4. 占位函数规则

第一阶段允许的占位包括：

- `toggleLocalePlaceholder()`
- `toggleIntermediateFramePlaceholder()`
- `estimateExportSizePlaceholder()`
- `showMessagePlaceholder()`
- `startCreateWigglePlaceholder()`

约束：

- 返回 `void`、固定空值或显式的 `notImplemented` 状态。
- 不弹出浏览器 `alert`，不输出虚假下载，不吞掉已有错误。
- 每个占位都对应后续实施清单中的唯一模块；实现后立即删除占位命名。

## 5. 阶段二：功能模块逐一实现

### 模块 A：预览流程与布局切换

- 上传后直接进入对齐预览。
- 复用现有 SBS/Top-Bottom 切分逻辑到右上角图标。
- MPO 图标显示但禁用，并提供提示。
- 重新上传清空旧文件设置。
- 对齐偏移上限使用单眼最短边的 20%。

验收：JPG/PNG 切换布局正确；MPO 不改变左右眼来源；不再依赖 Split Preview 页面。

### 模块 B：创建与预览切换

- 创建 Wiggle 时锁定工作区并显示加载状态。
- 完成后自动进入 Wiggle 预览并播放。
- “调整对齐”返回对齐预览；两个预览高度不变。

验收：多次往返不会复制计时器或产生旧任务复活。

### 模块 C：速度与中间帧

- Speed 仅接受 100–2000 的整数，默认 200ms。
- 中间帧默认关闭，支持四帧/两帧切换，切换后立即重新播放。
- Preview 与 GIF 共用帧序列和间隔。

验收：边界输入、非整数和粘贴非法值均有明确处理；两种序列导出一致。

### 模块 D：顶部消息

- 统一成功、警告、错误消息队列。
- 顶部居中、同类合并、自动消失；错误停留更久。
- 下载成功只显示“已下载”。

验收：连续错误不会堆叠遮挡；键盘和读屏可感知消息。

### 模块 E：加载与取消

- 上传/解析：上传区域或主工作区遮罩。
- 创建 Wiggle：主工作区遮罩。
- 导出：仅弹框主操作区和确认按钮锁定，取消导出保持可用；首次取消只中止导出并保留弹框，再次取消关闭弹框。

验收：取消、失败、重新上传后无需刷新页面；Reduced Motion 下不使用持续旋转动画。

### 模块 F：下载设置与记忆

- 默认 GIF + Medium。
- 记住上次有效格式和尺寸。
- GIF 下载弹框增加“导出取景”：默认“裁切重叠区”，可选“完整画面（保留边缘背景）”。仅在 GIF 时显示，不写入本地记忆，每次打开默认裁切重叠区。
- 裁切重叠区在原始解码尺寸上同时应用水平与垂直 Alignment，并以 Swap Eyes 后的最终绘制顺序计算共同可见区域；两眼原始尺寸不一致的 MPO GIF 也按最终绘制区域计算。交集边界向内取整，避免单像素边缘背景；A、B、M 帧共用同一裁切几何。先裁切、后按 Small、Medium、Large 的最长边规则缩放；裁切后的宽高比允许变化，不拉伸回原比例。完整画面沿用 Matte Background 与完整画布；Wiggle 预览与 MPO SBS PNG 不受该选择影响。
- 预计 GIF 大小与内存计划均按所选取景后的实际输出尺寸计算；切换取景后立即更新 Small、Medium、Large 的可用状态。零偏移时两个取景选项输出一致。
- GIF 各尺寸和 MPO SBS PNG 显示预计大小。
- 非 MPO 隐藏 SBS PNG；无效历史选择自动回退。
- 用户点击“确认下载”时记录反馈安全诊断中的格式、尺寸和 GIF 导出取景；即使该次导出随后失败或取消也保留。尚未尝试导出及 SBS PNG 的取景记为不适用，且不包含文件名或图片内容。

验收：预计大小明确标注“预计”；导出选择、实际输出和提示一致。

### 模块 G：中英文

- 默认中文，支持中文/英文切换并本地记忆。
- 覆盖主页面、使用指南、下载、隐私、反馈、顶部消息、错误与提示。

验收：刷新后保持选择；两种语言无截断；错误码不翻译。

## 6. 阶段三：真实文件兼容与回归

按 `compatibility.md` 依次验证：

1. Weeview 32.51MP SBS 上传、切分、对齐、两/四帧预览、三档 GIF。
2. FUJIFILM MPO 解析、方向、左右眼、GIF、SBS PNG。
3. 桌面 Chromium。
4. 移动视口和触屏操作。
5. WebKit/iOS 下载人工签收。

## 7. 阶段四：发布

- 功能分支推送产生 Vercel Preview。
- Preview 通过 UI 和核心下载验收；真实 Weeview/FUJIFILM 文件只在本地上传验收，不进入 Git、Vercel 或 CI Artifact。
- GitHub CI `release-check` 通过。
- 通过 PR 使用 Squash merge 合并生产分支后，由 Vercel 更新 `www.achillescat.com`。
- 上线后执行 deployment smoke；失败时立即回滚到上一成功部署。

## 8. 完成定义

- 不存在仍被页面调用的占位函数。
- `prd.md`、`ui.md`、`compatibility.md` 的 P0 条目全部有代码或验证证据。
- PC 与移动端没有横向溢出、遮挡或明显布局跳动。
- 真实 Weeview 与 FUJIFILM 样本完成核心闭环。
- Preview、CI、生产 smoke 均通过。
