# 开发循环

## 1. 适用范围

本文只定义长期可复用的开发循环、AI 协作方式、Definition of Done 和文档更新规则。
Vue 约定、Git 细节、测试工具和部署参数由项目自身文档负责。

## 2. 开发循环

1. 阅读根目录 `README.md`、`AGENTS.md`、`docs/STATUS.md` 和相关页面规格。
2. 明确本次任务的范围、唯一事实来源、验收条件和不在范围内的事项。
3. 先定位现有组件、composable、状态和 core 能力，优先复用已有边界。
4. 一次只推进一个可验收的变更单元。
5. 执行一次，查看首个真实错误，做最小修复，再从失败点继续。
6. 完成验收后更新 `STATUS.md`，并按文档更新规则同步受影响的规范。

## 3. AI 协作流程

- 开始前说明将读取或修改哪些文件；不因相邻问题扩大范围。
- 以当前代码和用户已确认的产品决策为准，不把草稿、截图或旧计划当作现行规则。
- 修改状态、资源生命周期、异步任务或 core 前，先检查 `ARCHITECTURE.md` 和调用方。
- 不创建重复 store、不绕过现有 composable、不用新依赖替代已有能力。
- 遇到设计冲突、架构突破或无法从现有资料推断的产品选择，暂停并提出决策，而不是猜测。
- 报告结果时说明已完成、未完成、验证结果和仍需用户决定的事项。

## 4. Definition of Done

- 需求范围内的代码或文档已完成，未引入未确认的相邻行为。
- 现有状态、资源清理、取消和错误路径没有被绕过或遗留旧任务。
- 相关页面规格、架构边界或质量门禁已同步；不重复复制其他文档的完整规则。
- 能执行的最小验证已完成，并记录真实结果。
- `STATUS.md` 反映当前事实，历史过程放入 `RELEASES.md` 或 `archive/`。

## 5. 文档更新规则

- `README.md` 只负责入口、项目是什么和如何启动。
- `PRD.md` 负责产品范围、业务规则和用户流程。
- `UI.md` 负责全局交互；`pages/<PAGE>.md` 负责页面结构和页面状态。
- `design/DESIGN_SYSTEM.md` 负责视觉语言；`design/DESIGN_CONCEPTS.md` 负责 v1 已批准概念基线。
- `ARCHITECTURE.md` 负责代码边界、状态所有权和资源生命周期。
- `QUALITY.md` 负责通用质量门禁；`COMPATIBILITY.md` 负责本项目真实文件、设备和浏览器矩阵。
- `STATUS.md` 只保留当前快照；过程记录、审计、计划和旧方案进入 `archive/`。
- 同一规则只保留一个来源，其他文档使用链接或简短引用。
