# 3D Photo Enhancer 产品需求

## 1. 文档状态

- 版本：v0.8
- 更新日期：2026-08-13
- 产品阶段：公开 Beta
- 本文是产品范围、用户流程和功能验收的唯一依据。
- UI 细节以 `ui.md` 为准，实施顺序以 `implementation.md` 为准，真实文件兼容以 `compatibility.md` 为准，发布方式以 `deployment.md` 为准。

## 2. 产品定位

3D Photo Enhancer 是浏览器内运行的双视图照片工具。用户上传 SBS、Top-Bottom 或 MPO 照片，完成布局确认、左右眼对齐、Wiggle 预览并下载 GIF；MPO 还可导出 SBS PNG。

图片内容默认只在浏览器本地处理，不上传服务器。本产品不从普通单张 2D 照片生成真实 3D，不承诺修复严重旋转、缩放、透视、镜头畸变或不同时间拍摄造成的主体运动。

## 3. 必须支持的输入

- JPG/JPEG：左右拼接 SBS、上下拼接 Top-Bottom。
- PNG：左右拼接 SBS、上下拼接 Top-Bottom。
- MPO：至少兼容仓库中的 FUJIFILM 真实样本。
- Weeview 32.51MP SBS：8064 × 4032，总像素 32,514,048，每眼 4032 × 4032，属于必须通过的正式兼容基线，不能因预览降采样、内存保护或 UI 重构而失去支持。

不支持：普通单张 2D 照片、HEIC、WebP、视频、压缩包、两张独立照片上传。

## 4. 核心流程

1. 用户点击整个上传区域或把文件拖入上传区域。
2. 页面显示上传/解析遮罩；新文件会直接替换旧文件，并清除旧文件的布局、对齐、播放和导出临时状态。
3. 解析完成后直接进入“对齐预览”，不再显示 Split Preview。
4. JPG/PNG 可用右上角图标切换 SBS 与 Top-Bottom；MPO 始终显示该图标但置灰，并提示“仅适用于 JPG/PNG 拼接图”。
5. 用户在叠加预览中调整水平、垂直和叠加强度，或使用“重置对齐”。
6. 用户点击“创建 Wiggle”；页面显示创建遮罩，完成后自动进入 Wiggle 预览并自动播放。
7. 用户设置每帧间隔、暂停/播放、交换左右眼、开启/关闭中间帧或返回调整对齐。
8. 用户打开下载弹框，选择输出格式和尺寸并开始导出。
9. 导出时只锁定弹框主操作区和确认按钮，取消导出始终可用。
10. 下载成功后顶部只提示“已下载”，不显示最终文件大小。

## 5. Wiggle 规则

- 中间帧默认关闭；开启时固定 `A → M → B → M` 四帧，M 为 A 100% 后叠加 B 50%。
- 中间帧关闭时固定 `A → B` 两帧。
- 切换中间帧后立即从新序列开始播放，并直接影响 GIF 导出。
- Speed 表示每帧间隔，只接受 100–2000 的整数毫秒，默认 200ms。
- 200ms 时，四帧完整循环为 800ms，两帧完整循环为 400ms。
- 预览与导出必须使用相同的左右眼顺序、对齐参数、帧序列和帧间隔。
- 不提供 Wiggle Amount、帧数自定义或 Speed Reset。

## 6. 对齐与画面规则

- 对齐预览将两眼画面叠加显示，不并排显示。
- 调节项为水平偏移、垂直偏移、叠加强度。
- 水平与垂直偏移的可调上限统一为单眼最短边的 20%。
- “重置对齐”只重置上述三项。
- 预览及选择“完整画面（保留边缘背景）”的 GIF 保持完整画面和真实比例，不通过自动裁切或缩放隐藏偏移边缘；只有用户在 GIF 下载弹框显式选择“裁切重叠区”时才裁切共同可见区域。
- 露出区域使用统一 Matte Background。

## 7. 下载规则

- 普通 JPG/PNG：仅导出 GIF。
- MPO：可导出 GIF 或原始解码尺寸的 SBS PNG。
- GIF 默认格式为 GIF，默认尺寸为 Medium；Small、Medium、Large 的最大边分别为 480、720、1024，禁止无提示放大源图。
- GIF 下载弹框提供“导出取景”：默认“裁切重叠区”，可选“完整画面（保留边缘背景）”。
  - 裁切重叠区：同时使用当前水平与垂直对齐参数，并以 Swap Eyes 后的最终绘制顺序计算两眼共同可见区域；A、B、M 帧共用同一裁切区域。交集边界向内取整，避免残留单像素边缘背景。两眼原始尺寸不一致的 MPO GIF 同样按最终绘制后的共同可见区域计算。裁切后的宽高比允许随对齐偏移变化，不拉伸回原比例；再按 Small、Medium、Large 的最长边规则缩放输出，因此无白边但会裁切边缘。
  - 完整画面：保留完整画布与现有 Matte Background，不裁切、不拉伸，可能出现边缘背景。
  - 预计文件大小、内存预算和 Small、Medium、Large 的可用状态均按所选取景后的实际 GIF 尺寸计算；切换取景后立即重新计算。完整画面沿用完整画布尺寸。
  - 该选择只影响本次 GIF 导出，不影响 Wiggle 预览、MPO SBS PNG 或后续下载弹框；不写入本地记忆，每次打开弹框均默认“裁切重叠区”。零对齐偏移时两个选项的输出一致。
- 下载弹框记住用户上一次有效的格式与尺寸选择；选择对当前文件无效时回退到 GIF + Medium。
- GIF 每个尺寸显示预计文件大小；MPO 的 SBS PNG 也显示预计文件大小。预计值不是最终值，不得写成精确大小。
- MPO 两眼尺寸不一致时阻止 SBS PNG 导出，并给出顶部错误消息。
- 导出支持取消；导出期间首次点击“取消导出”只中止导出并保留下载弹框，取消后再次点击“取消”才关闭弹框；取消或失败后保留当前编辑状态。

## 8. 全局界面规则

- 默认语言为中文，可切换英文；语言选择本地记忆，覆盖页面、弹框、顶部消息、隐私政策和反馈文字。
- 使用指南位于页面右上角，紧挨语言切换左侧。
- 版本、隐私政策和反馈位于页面底部。
- 成功、警告、错误等消息采用顶部居中的 ElMessage 式提示；同类消息合并，普通消息自动消失，错误停留更久。
- 上传解析、创建 Wiggle、导出均有清晰的加载状态，且遵守 `prefers-reduced-motion`。
- 打开使用指南或下载弹框时，Wiggle 继续播放。

## 9. 隐私与反馈

- 图片像素、原始 MPO 内容和输出文件不上传。
- 可选分析未获得明确同意时不得发送。
- 分析事件不得包含文件名、图片内容、原始字节或可逆图片标识。
- 反馈只附带版本、构建号、浏览器、输入格式、导出选项（格式、尺寸与 GIF 导出取景）和错误码，不附带文件名或图片内容。仅在用户点击“确认下载”后记录该次导出选项；即使随后导出失败或取消，仍保留该次尝试用于反馈诊断。尚未尝试导出及 SBS PNG 的导出取景均标记为不适用。

## 10. 发布最低条件

- 桌面端和移动端布局符合 `ui.md`，无横向溢出。
- Weeview 32.51MP SBS 与 FUJIFILM MPO 核心流程通过。
- 中英文、顶部消息、三个加载状态和下载取消可用。
- Preview 与导出帧语义一致。
- `npm run release:check` 通过。
- Vercel Preview 验收通过后，才能合并到生产分支。

## 11. 暂不进入本轮

- 两张独立图片上传。
- 自动对齐、旋转、缩放、透视修复。
- 红蓝 3D、MP4/WebM/APNG/WebP。
- AI 深度、新视角生成、在线分享、账号、云存储、批量处理。
